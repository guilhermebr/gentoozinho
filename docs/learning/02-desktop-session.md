# 02. The desktop session (what phase 2 taught)

Learned on 2026-09-28 by getting a gentoozinho VM to boot into SDDM, log
into Hyprland, and take its own screenshot. Each section: the mechanism, what
we did with it, what broke.

## Git live ebuilds and git-r3

- `app-misc/gentoozinho-9999` inherits `git-r3` and sets `EGIT_REPO_URI`. At
  merge time the eclass clones the repository and records the commit in
  `/var/db/pkg/app-misc/gentoozinho-9999/EGIT_VERSION`.
- A live ebuild has **no `KEYWORDS`**, so `~amd64` in `package.accept_keywords`
  does not unmask it; it needs `app-misc/gentoozinho **`.
- Portage never re-merges an installed `9999` on a world update. The installer
  runs `emerge --oneshot app-misc/gentoozinho` on every run when the live
  version is installed, otherwise a re-run keeps a stale payload. We shipped a
  stale hyprpaper fix this way once before noticing.
- To test uncommitted work, git-r3 can be pointed at a local checkout with
  `EGIT_OVERRIDE_REPO_<ID>` and `EGIT_OVERRIDE_BRANCH_<ID>`. The `<ID>` is
  derived from the **repository URL** (`guilhermebr/gentoozinho.git` becomes
  `GUILHERMEBR_GENTOOZINHO`), not from the package name. It clones committed
  HEAD only, so the smoke test refuses to run on a dirty tree.
- A keyworded package must not depend only on a live ebuild: `pkgcheck` flags
  `NonsolvableDepsInStable` because stable profiles cannot see `9999`. The
  answer is a versioned snapshot ebuild (`0.2.0_alpha2`) built from a GitHub
  tag tarball, with a `Manifest` generated by `ebuild <file> manifest`. The
  installer still prefers `9999` through `**`.

## How a Wayland session starts on systemd Gentoo

1. `sddm.service` starts. Our `/etc/sddm.conf.d/10-gentoozinho.conf` sets
   `DisplayServer=wayland` and runs Hyprland as the greeter's compositor with a
   minimal config (`default/sddm/hyprland.conf`), like Omarchy does.
2. SDDM lists `/usr/share/wayland-sessions/*.desktop`. Ours runs
   `uwsm start -g -1 -e -D Hyprland hyprland.desktop`.
3. uwsm starts Hyprland as a systemd user unit and puts every `exec-once`
   launched through `uwsm-app --` into its own scope under
   `app-graphical.slice`. `journalctl --user -b` then shows each daemon.
4. `systemctl --user import-environment` and
   `dbus-update-activation-environment` hand the session variables to systemd
   and dbus, which is what lets portals and later apps find the display.
5. `--autologin` writes an `[Autologin]` section with `User` and
   `Session=gentoozinho.desktop`; this is how the smoke test reaches a running
   session with nobody typing a password.

## PAM, portals, polkit

- Gentoo ships `/etc/pam.d/hyprlock` (`auth include login`), so hyprlock works
  without any PAM edits.
- `xdg-desktop-portal` picks `hyprland.portal` and `gtk.portal`; both were
  installed by the desktop meta and appear in
  `/usr/share/xdg-desktop-portal/portals/`.
- The polkit agent is `/usr/libexec/polkit-gnome-authentication-agent-1`
  (`gnome-extra/polkit-gnome`), started from autostart.

## hyprlang `.conf` today, Lua tomorrow

- Hyprland 0.56.2 still parses the classic `.conf` (`Hyprland
  --verify-config` prints `config ok` for our assembled config), which let us
  port Omarchy v3.8.4's hyprlang files directly.
- The running session shows a notification: **".conf config format, support
  for which will be removed in Hyprland 0.57"**. Even hyprctl's own recovery
  hint is Lua now (`hyprctl eval 'hl.clear_crashed_lockscreen()'`). The Lua
  migration is the next structural job; Omarchy 4 already did it upstream.

## The theme engine

- One `colors.toml` per theme; `default/themed/*.tpl` templates use
  `{{ key }}`, `{{ key_strip }}` (no `#`) and `{{ key_rgb }}` (`r,g,b`).
  `gentoozinho-theme-set-templates` turns the toml into a sed script and
  renders every template that the theme did not ship verbatim.
- `gentoozinho-theme-set` stages into `current/next-theme`, renders, then swaps
  the directory in atomically and records `theme.name`. Every reload is
  guarded by `pgrep`, so the installer can set the theme before any session
  exists.
- GTK css cannot `@import` a `~` path. walker's and swayosd's style sheets
  import a relative file (`gentoozinho-colors.css`, `colors.css`) that
  `gentoozinho-theme-set` symlinks to the rendered fragment.
- walker 0.13 (GURU) predates Omarchy's elephant backend; its config is the
  upstream default with `theme = "gentoozinho"`, and its css needs
  `@define-color color1` besides foreground and background.

## Wallpapers: swaybg, not hyprpaper

- hyprpaper 0.8 is built on hyprtoolkit and aquamarine. On the VM it
  segfaulted every start: `DRM_IOCTL_MODE_CREATE_DUMB failed: Permission
  denied`, then a failed GBM allocation. Without a real GPU driver it cannot
  allocate buffers.
- swaybg draws through shared memory and works anywhere. Omarchy v3.8.4 used
  it too. `gentoozinho-theme-bg-next` restarts it when the background changes.

## Graphics in a VM

- The cloud image carries `/etc/kernel/config.d/dist-amd64-livecd.config`
  with `CONFIG_DRM=n`. Any kernel rebuilt with it has no graphics drivers at
  all (no `/dev/dri`). The installer removes the snippet before the packages
  stage; when no installed kernel has DRM modules it installs
  `sys-kernel/gentoo-kernel-bin` and unmerges the source kernel.
- QEMU: use `-vga virtio`, not `-device virtio-vga`. Replacing the default VGA
  shifts PCI slots, the NIC gets a new name and the cloud image's network
  config stops matching.
- Mesa in the VM has no `virgl` driver (`VIDEO_CARDS`), so Hyprland renders
  on `kms_swrast` (llvmpipe). It works; it is slow; `VIDEO_CARDS="virgl"` is a
  phase 3 item for the vm profile.

## Taking a screenshot over SSH

    export XDG_RUNTIME_DIR=/run/user/$(id -u)
    export HYPRLAND_INSTANCE_SIGNATURE=$(ls $XDG_RUNTIME_DIR/hypr | head -1)
    export WAYLAND_DISPLAY=$(ls $XDG_RUNTIME_DIR | grep -m1 '^wayland-[0-9]$')
    grim /tmp/shot.png

`grim` blocks when the display is DPMS-off; hypridle turns it off 330 s after
boot, so the smoke test shoots right after login. `hyprctl dispatch dpms on`
wakes it. Killing hyprlock while locked shows Hyprland's "lockscreen app
died" page, which is not a hyprlock crash.
